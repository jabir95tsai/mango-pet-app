# iOS 遛狗路線紀錄與家庭即時位置 v1

狀態：**Backend 已部署、Linux gate READY；iOS 通知簽章已修復，preview build FINISHED；待批次實機驗收**
日期：2026-11-15｜角色：iOS PM｜依據：本次使用者 Q1–Q22 決策與新增回到起點提醒需求。  
平台：iOS 優先；Web 新地圖與查看入口另行交接，不在本版交付範圍。

## 1. 目標與範圍

作為帶狗散步的人，我想把手機鎖屏放入口袋，仍能記錄整趟散步路線，完成後與家人回顧；每次可自行選擇讓家人在散步期間查看最新位置。若回到起點忘記結束，收到一次提醒。

第一版交付：

- 手機定位、前景與背景路線紀錄、完整保存、結束後地圖回顧。
- 家庭內即時位置：每次開始前手動開啟，預設關閉，不沿用上次選擇；結束停止。
- 家庭歷史路線：不論是否曾開啟即時分享，完成存檔後目前家庭成員均可查看。
- 斷網保存、失訊缺口、中斷恢復、權限降級、6 小時上限。
- 離開再返回起點附近並停留 5 分鐘，提醒一次，不自動結束。

不做：寵物 GPS 硬體／走失追蹤、時間軸動畫回放、家庭查看當次進行中的完整軌跡、公開分享連結、途中單獨關閉分享、鎖定畫面小工具／Live Activities／動態島、重複催促、通知家人回家、Web 新功能。第一版開啟分享後需結束散步才能停止；此限制開始前須可理解。

## 2. 現況與採用方向

本次唯讀盤點依目前 checkout，非部署或實機驗證；git fetch 因 FETCH_HEAD 寫入受限失敗，遠端未更新。

| 現況證據 | 對本版的影響 |
|---|---|
| `apps/ios/src/lib/walk-tracking-service.ts` 已有背景定位、session 持久化與恢復 | 擴充既有流程，不另建第二套追蹤生命週期 |
| `packages/shared-business/src/gps.ts` 採 rolling 500 點、超過丟掉最早點 | 不能直接畫現有 path 就宣稱完整；新路線需保留整趟有效樣本與斷點 |
| `packages/shared-types/src/index.ts` 的 path 點只有 lat/lng/t | 需要能表達中斷區段的資料契約 |
| `firestore.rules` 的 walks 家庭讀取權限 | 沿用家庭共同歷史紀錄；新增即時資料仍需獨立驗證成員與 session 權限 |
| `docs/features/ios-p1-walks.md` 曾排除 live map、即時分享與回放 | 本規格新增 iOS 歷史地圖及最新位置分享；動畫回放仍延後 |

已討論的產品方案：僅散步後回顧（不足以滿足家人查看）、回顧＋家庭即時位置（使用者選定）、再加動態島／鎖屏顯示（使用者延後）。

工程建議（PM 建議，非已確認技術選型）：沿用 native 定位服務與同一 Firebase project，把完整歷史路線、進行中最新位置及完成的散步摘要分開管理。不要把進行中 session 提早寫成已完成 Walk 觸發既有排行榜／動態。確切 collection、分段儲存方式、地圖套件與上傳批次交 Backend／Feature Builder 評估並記錄，不在本文件假定已選定。

## 3. 已確認行為

### 3.1 開始、定位與完整路線

- 追蹤帶狗者手機，不代表狗離開手機後的實際位置。
- 延用現有選寵物與開始散步流程；開始前選擇是否向家庭即時分享。
- 有背景權限：鎖屏、切換 App 仍持續記錄；拒絕背景權限：可前景追蹤，但明示鎖屏後可能無法記錄。
- 完全拒絕定位：只能計時或手動補登，不產生路線、即時位置或返家偵測。
- 完整指整趟取得的有效路線均保留，不因點數上限丟掉前段；不承諾失訊期間也有實際路徑。
- 離線時保存有效定位，恢復連線後補存；本地資料在伺服器確認完整保存前不得清除。重試不得重複建立 Walk 或計分。
- 定位失訊、中斷、既有暫停／繼續流程造成的缺口需分段；不把缺口直接畫成實際步行路線或累加成步行距離。
- 本規格不新增暫停控制；若沿用既有暫停，必須保留分段語意，不暗示暫停等於關閉分享。

### 3.2 家庭即時位置

- 每次開始前自行開啟；只向該家庭目前成員提供最新位置、定位時間、帶狗者與寵物。
- 不向家人提供當次進行中的歷史軌跡；開始分享前的點不補成即時軌跡。完成存檔後依歷史權限查看。
- 正常定位與網路下，以約 15–30 秒更新為驗收目標，需實機測量；不是每秒追蹤或保證延遲。
- 每個位置顯示定位時間。超過 1 分鐘無新有效位置：標示可能過時；超過 5 分鐘：不再展示即時位置。
- 6 小時截止優先於上述 5 分鐘寬限：即時位置最晚可見時間為「定位時間＋5 分鐘」與「最初開始＋6 小時」兩者較早者，家人端不等待新封包才隱藏。
- 不能以重送舊座標、重新收到快取或僅更新心跳時間把舊位置變成新位置。
- 結束時本機立即停止追蹤及後續即時位置發布；線上時同步結束狀態。離線結束時家人端依上述過期機制處理，恢復連線後補送結束狀態。
- 結束後的補傳只可用於歷史保存，不得重新啟用即時分享；延遲封包不得把 ended session 改回 active。
- 途中單獨關閉分享延後；回到起點提醒本身不會停止分享。

### 3.3 歷史地圖與權限

- 完成後可從散步歷史進入地圖，查看路線、起終點、既有距離與時間；有缺口或尚未補存完成時清楚標示。
- 未開即時分享的家庭散步，完成後也讓目前家庭成員看完整路線；開始前須說明兩種分享不同。
- 新加入成員可看家庭歷史；退出／被移除者不得再取得家庭路線或即時資料。已被截圖／另行保存的資料無法收回。
- 路線跟隨散步紀錄長期保存；刪除 Walk 時相關路線一併刪除，刪除後不可被離線重試重新建立。
- 單獨刪除路線與自動到期清理不在 v1。
- 舊紀錄已丟失的點不重建；無 path 的舊紀錄／手動補登顯示無路線。舊 path 只能當既有資料呈現，不宣稱完整。

### 3.4 中斷恢復與 6 小時限制

- App 中斷後重新開啟，提供繼續這次散步或結束並保存已記錄部分；中斷區間標示缺口。
- 原先有開即時分享，選擇繼續時告知分享將恢復；原先未開不得自動打開。
- 單次最長 6 小時，到期結束定位、停止分享、保留紀錄；開始前說明限制。
- PM 補充工程解讀：6 小時按最初開始時間的實際經過時間計算，重開／暫停／恢復不重置。到期 session 不得繼續或被舊封包復活。
- 不把鎖屏背景執行等同於強制關閉、關機或任何狀態下都能持續執行。到期後客戶端取得執行機會時必須先終止 session，不再接受超時樣本；伺服器也須拒絕超時分享。精確背景執行能力須實機驗證，若不足須回報，不宣稱無條件準時執行。

### 3.5 回到起點提醒

使用者確認的門檻：先離起點超過 **200 公尺**，再返回起點 **100 公尺內**，連續停留 **5 分鐘**，每次散步最多提醒 **1 次**。

- PM 補充：起點取本次第一個有效定位點，不以住宅地址或開啟頁面的位置推定。
- 未曾離開 200 公尺不觸發，避免出門準備時誤提醒。
- 以有效定位在範圍內持續停留判定，不要求 GPS 座標完全不動；它不是精確的「人在家」或靜止偵測。
- PM 補充：離開 100 公尺範圍則重計 5 分鐘；定位缺口不能當作已確認停留，待新有效樣本重新判定。避免 GPS 漂移的品質與取樣規則由工程定義並測試。
- 提醒文案方向：「到家了嗎？記得結束散步。」點擊進入目前散步，使用者自行結束；不直接自動結束。
- 無回應則繼續記錄與原有分享，仍受 6 小時上限限制。
- 通知權限拒絕不阻擋散步；回到 App 可看到提醒。已提醒狀態須持久化，App 重開不重複通知；已結束的 session 不發舊提醒。
- 這些距離與時間為 v1 起始門檻；實機若需要調整，記錄證據並回 PM，不暗改已確認行為。

## 4. PM 補充預設與設計約束

以下是為交接可執行而補入的預設，不冒充訪談中逐項確認的決策：

- 個人模式保留私人路線，沒有家庭時不提供即時分享；不能因日後加入家庭自動把個人紀錄公開。
- 家庭 session 綁定開始時的家庭，不因中途換家庭把位置轉發到新家庭；失去原家庭資格即停止家庭發布，保留本地紀錄供恢復。後續歷史歸屬若與現有家庭／寵物規則衝突，Backend 必須回 PM 裁決，不放寬權限。
- v1 不新增分享中途開啟入口、散步者自己的即時路線地圖、導航或地圖離線下載；離線紀錄不等於離線底圖可用。
- 一次以既有單 session／寵物流程為準，不新增接力或多人合併追蹤。家庭可同時查看不同成員各自的分享。
- 家人只取得最新位置；歷史原始路線在完成前不得因資料結構便利而被提前讀取。
- 位置過期與成員撤權須涵蓋伺服器讀取權限及 App 已開啟畫面的清除，不能只藏入口。
- PM 補充快取預設：v1 不提供家庭歷史路線離線瀏覽；查看者偵測斷網、權限失效或無法重新確認家庭資格時停止呈現家庭路線及即時位置，重新連線後先確認權限再顯示。散步者自己的本地紀錄不受此限制。未偵測到網路變化之前無法保證立刻獲知遠端撤權，不承諾遠端抹除已取得的資料。
- UI 遵守 [design-system](../design-system.md)：共用 mango tokens、radius、既有平台元件規則、reduced-motion、Dynamic Type／VoiceOver；位置新鮮度不能只靠顏色辨認。本文不重定義視覺樣式。

## 5. 驗收清單

以下均為待執行，未因本規格寫成而視為通過。

| 情境 | 預期結果 |
|---|---|
| 正常散步，鎖屏／切換 App | 有效路線持續記錄；完成可看起終點及整趟路線 |
| 超過 500 個有效點 | 起點和前半段仍保存；距離與地圖不因 rolling cap 分歧 |
| 途中無網路，結束後恢復 | 本地資料保留、只存一筆 Walk、歷史補齊、不重新開分享 |
| GPS 失訊／暫停／App 中斷 | 路線分段，缺口不偽造、不跨缺口增加步行距離 |
| 即時分享開／關各一趟 | 開啟才有即時位置；兩趟完成後家人皆可查看歷史 |
| 兩支 iPhone、背景分享 | 測量 15–30 秒更新目標、定位時間與耗電，記錄偏差 |
| 無更新 >1 分鐘／>5 分鐘 | 分別顯示過時／移除即時位置；舊資料重送不刷新年齡 |
| 線上與離線結束 | 定位停止；線上關閉分享，離線依過期規則；延遲點不復活 |
| 新成員／退出／被移除／非成員 | 新成員可看歷史；其餘無家庭讀取權；已開畫面撤權 |
| 查看者離線時被移除，再連線 | 偵測離線時隱藏家庭位置／路線；重新連線先驗權限，不從快取重新展示 |
| 拒背景／拒全部定位／拒通知 | 對應降級與提示正確，不生成不存在的路線或阻擋可用流程 |
| 中斷後繼續／結束 | 既有點保留、不重複存檔，分享恢復提示正確 |
| 6 小時、重開、延遲上傳 | 到期終止、不重置時限、不接收超時分享，已記錄資料保存 |
| 5:59 收到位置，之後無新封包 | 到 6:00 隱藏即時位置，不延長至 6:04 |
| 尚未離起點 200m 就停留 | 不提醒 |
| 已離開 >200m，回到 ≤100m 停留 5 分鐘 | 提醒一次；點開回到散步；不自動結束 |
| 停留不足、再離範圍、失訊、重開 | 不提前提醒；依規則重計；一趟不重複提醒 |
| 無通知權限／已結束 | 前者 App 內可見提醒；後者不發殘留通知 |
| 刪除散步、重試上傳、舊紀錄 | 路線同步刪除且不復活；舊資料不假稱完整 |
| Web 舊版與 shared contract | 既有散步／排行榜／動態／刪除流程相容，不要求 Web 同時新增地圖 |

## 6. 工程交接與交付順序

工作量屬跨 iOS 與共用 backend 的功能，不能當成只加一張地圖的小改動。

1. **iOS Backend／Backend**：先提出 session、完整分段路線、最新位置與完成 Walk 的資料契約；評估讀寫成本、限制與保存；完成 rules／撤權／過期／結束優先／刪除／重試冪等的設計與測試。共用 types 同步、保護 Web 舊客戶端；不建立新 Firebase project。
2. **iOS Feature Builder**：依資料契約擴充既有追蹤與持久化服務、補傳、恢復、6 小時限制、起點停留提醒、歷史地圖及家庭最新位置；選地圖套件前確認當前 Expo 相容性與成本。記錄背景可靠性限制。
3. **iOS UI/UX**：設計開始前分享說明、權限降級、路線缺口／保存中／過時位置／恢復提示、歷史地圖與家庭查看入口。沿用設計 SoT，不重做整頁風格。
4. **Cross-platform PM／Web handoff**：記錄 iOS-first 差異，另排 Web 地圖／位置查看是否跟進；不把本版授權擴成 Web 新功能。檢查 shared schema 與現有家庭政策相容。
5. **iOS PM**：整個功能收齊後安排一次 phase 批次實機驗收；涵蓋兩帳號兩裝置、鎖屏、弱訊號、斷網、權限、通知與耗電。過程各 sub-phase 自動檢查，不反覆要求使用者安裝。

工程必要關卡：受影響專案 typecheck、定位／時間狀態機測試、rules 權限與過期測試、儲存重試／刪除驗證；碰 dependencies／lockfile 時依 [team README](../team/README.md) branch-first + Linux build gate。地圖與背景定位需真機驗收，靜態檢查不能代替。

實作前需完成的技術確認：背景／終止狀態下的可達行為、通知觸發方式、地圖套件、路線分段／上傳契約、GPS 缺口判準及可接受耗電；若無法滿足本文件目標需明列差距回 PM，不暗自降規。

實作與驗證狀態見 [iOS 交付紀錄](ios-walk-route-implementation.md) 及 [Backend 契約](walk-route-backend-contract.md)。Backend 已部署，iOS build 狀態見發布紀錄；本文驗收表不因此自動視為實機通過。
